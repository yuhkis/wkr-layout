# わから配列 / Wakara Layout (wkr)

> `w` `e` `r` と打つだけで「わから」と入力できます（`w`=わ行、`e`=か行、`r`=ら行）。配列名 **wkr** は「**w**a-**k**a-**r**a」の略です。
>
> Type `w` `e` `r` to input "わから" (`w`=Wa, `e`=Ka, `r`=Ra). The name **wkr** stands for **w**a-**k**a-**r**a.

**わから配列**は、[きゅうり改](https://www.itmedia.co.jp/enterprise/articles/0704/24/news006_2.html)をベースに大幅に改良した、ローマ字入力ベースの日本語かな入力配列です。子音キー＋母音キーの2打鍵で1つのかなを入力します。

**Wakara Layout** is a Japanese kana input method based on romaji-style two-stroke key sequences, significantly improved upon [Kyuuri-Kai](https://www.itmedia.co.jp/enterprise/articles/0704/24/news006_2.html). Press a consonant key followed by a vowel key to produce a kana character.

## 背景 / Background

QWERTYローマ字入力では右手首への負担が大きく、長時間の入力で疲労が蓄積します。わから配列は、この問題を解消するために設計しました。ver 0.2 の完成は 2018年で、作者自身が約8年間日常的に使い続けています。

Standard QWERTY romaji input places disproportionate strain on the right wrist. Wakara Layout was designed to address this problem. Version 0.2 was completed in 2018, and the author has been using it daily for about 8 years.

- ローマ字ベースで覚えやすく、打鍵数を極力減らしたい
- できるだけ滑らかに、手首の引っ掛かりがなく入力したい
- ホームポジションから、できるだけ離れずに入力したい

- Easy to learn with romaji-based rules, while minimizing keystrokes
- Smooth, fluid typing without wrist strain
- Stay as close to the home position as possible

## オリジナリティ / What Makes It Different

ローマ字入力と比べて、**1押下で確定の「かな文字」が増えています**：

| | 1打鍵で確定する文字 |
|:---|:---|
| ローマ字入力 | あ い う え お（5文字） |
| **わから配列** | **あ い う え お や ゆ よ ん っ ー**（11文字）|

さらに、子音キー1打で行の先頭（あ段）も即時確定するため、か さ た な は ま ら わ が ざ だ ば ぱ ふぁ も実質1打鍵です。

---

Compared to standard romaji, **many more characters are produced with a single keystroke**:

In romaji, only **5 characters** (あいうえお) resolve in one keystroke. With Wakara Layout, **11 characters** resolve in one keystroke: あ い う え お や ゆ よ ん っ ー.

Additionally, each consonant key immediately produces the あ-column kana of its row, so か さ た な は ま ら わ が ざ だ ば ぱ ふぁ are also effectively single-keystroke inputs.

## 方法 / How It Works

### 左右交互入力を基本とする / Alternating left-right input

右手ホームポジション `H` `J` `K` `L` `;` に「あ う い お え」を割り当て、左手で子音、右手で母音を打ちます。

Vowels are mapped to the right-hand home row (`H`=あ, `J`=う, `K`=い, `L`=お, `;`=え). Left hand selects the consonant, right hand selects the vowel.

### 同じキーの連打を減らす / Reduce same-key repetition

- `N` → 「ん」に独立割り当て（1ストロークで確定）
- `M` → 「っ」に独立割り当て（1ストロークで確定）

### 子音1入力で「あ列」を入力可能にする / Single consonant produces あ-column kana

- `e` → 「か」、`e` `k` → 「き」 のように割り当て
- `e` `s` → 「かさ」、`e` `s` `k` → 「かし」 のように連続入力が可能

### 拗音は左右交互の2ストロークで入力 / Contracted sounds in two strokes

- 「た」+「や」→「ちゃ」、「た」+「ゆ」→「ちゅ」 のように割り当て

### 捨て仮名の単独入力も可能 / Small kana input

- `□` `H` → 「ぁ」、のように □（`T`キー）レイヤーで入力します
- **前置形のみです。** ver 1.0 のテーブルには「母音キーの後に `T`」という後置形も
  入っていましたが、母音キーの次の `T` を必ず吸ってしまい、`K` `T` `;` が「いぇ」ではなく
  「ぃえ」になるなど、基本かな＋捨て仮名の組み合わせを潰していたため ver 1.1 で削除しました /
  **Prefix form only.** The ver 1.0 tables also carried a postfix form, which swallowed the
  `T` of a following prefix small kana; it was removed in ver 1.1.

### 特殊入力 / Special characters

- `E` `Y` → 「ヶ」、`Q` `Y` → 「ヵ」、`W` `Y` → 「ゎ」 のように ■（`Y`キー）レイヤーで入力
- `W` `J` → 「ゔ」。カタカナの「ヴ」は変換で得ます。`W` `J` `□` `H` → 「ゔぁ」のように
  捨て仮名を続けられるので、「ヴァイオリン」も一続きで変換できます /
  `W` `J` gives ゔ; ヴ comes from conversion, and small kana can follow it.
- `■` `J` → 「↓」、`■` `C` → 「〇」 のように記号も入力可能
- `■` `I` → 「【」、`■` `O` → 「】」（`■` `(` / `■` `)` でも入力可）
- その他、余ったキーは自由に割り当てできます

### macOS 標準の日本語入力 / Apple Japanese Input (macOS)

[**yuhkis/wkr-macos**](https://github.com/yuhkis/wkr-macos) を使います。Apple日本語入力の前段で
物理キーをわから配列として解釈し、標準ローマ字へ翻訳して打ち直す常駐アプリなので、
Apple日本語入力の変換エンジン・学習・Space変換はそのまま使えます。

Use [**yuhkis/wkr-macos**](https://github.com/yuhkis/wkr-macos). It sits in front of Apple Japanese
Input, interprets your physical keystrokes as the Wakara layout, and replays the equivalent standard
romaji, so Kotoeri's conversion engine, learning, and Space conversion all keep working.

1. [wkr-macos](https://github.com/yuhkis/wkr-macos) を clone して `make app` でビルド /
   clone and build with `make app`
2. `/Applications` へ配備し、「入力監視」「アクセシビリティ」を許可 /
   install to `/Applications`, then grant Input Monitoring and Accessibility
3. Apple日本語入力の「ひらがな」を選んで起動 / select Hiragana and launch

手順の詳細: [docs/install.md](https://github.com/yuhkis/wkr-macos/blob/main/docs/install.md) /
Full instructions: [docs/install.md](https://github.com/yuhkis/wkr-macos/blob/main/docs/install.md)

> **⚠️ 前提:** **JISキーボード専用**です。ソースからビルドする必要があり、署名済みバイナリの配布はありません。 /
> **⚠️ Requirements:** **JIS keyboard only.** Build from source; no signed binary is distributed.

### Google 日本語入力 / Google Japanese Input

1. 同梱の [v1.1 `romantable.txt`](../google-japanese-input/romantable.txt) を使用 / Use the bundled v1.1 table
2. Google 日本語入力の「プロパティ」を開く / Open Google Japanese Input "Properties"
3. 「一般」タブ →「ローマ字テーブル」→「編集」→「インポート」 / "General" tab → "Romaji table" → "Edit" → "Import"
4. ダウンロードした `romantable.txt` を選択 / Select the downloaded `romantable.txt`

### azooKey (macOS)

1. 同梱の [v1.1 `custom_input_table.tsv`](../azookey/custom_input_table.tsv) を使用 / Use the bundled v1.1 table
2. azooKeyの入力方式を「カスタム」に設定 / Set azooKey input method to "Custom"
3. 「編集」→「ファイルに書き出し」で `custom_input_table.tsv` の保存場所を確認 / "Edit" → "Export to file" to locate `custom_input_table.tsv`
4. 書き出された `custom_input_table.tsv` をダウンロードしたファイルで差し替え / Replace the exported file with the downloaded `custom_input_table.tsv`

> **⚠️ azooKeyの注意点：** Google日本語入力では子音キーを押した時点で変換候補が表示されます（例：`w` → 「わ」）が、azooKeyでは途中経過が表示されず `w` のまま表示されます。次の文字（例：`。`）を入力するか、スペースキーで変換すれば正しく「わ」に変揖されますが、**文末で何も入力せずにEnterを押すと `w` のまま確定されてしまいます。** 文末ではスペースで変換するか、句読点や次の文字を入力してから確定してください。
>
> **⚠️ Note for azooKey:** Google Japanese Input shows kana conversion immediately when a consonant key is pressed (e.g., `w` → "わ"), but azooKey displays the raw consonant (e.g., `w`) without showing the intermediate kana. Typing the next character (e.g., "。") or pressing Space to convert will correctly resolve it, but **pressing Enter at the end of a sentence without additional input will commit the raw consonant as-is.** Always press Space to convert, or type punctuation or the next character before confirming at the end of a line.

## 実装ごとの差分 / Differences Between Implementations

**このREADMEは、作者が日常的に使用している [wkr-macos](https://github.com/yuhkis/wkr-macos) の
実装内容を基準に記述しています。** 本リポジトリで配布している Google 日本語入力用・azooKey 用の
テーブルは ver 1.0 のもので、次の点が異なります。作者が実機で確認できているのは macOS 版のみです。

**This README describes the layout as implemented in
[wkr-macos](https://github.com/yuhkis/wkr-macos), which the author uses daily.** The Google
Japanese Input and azooKey tables distributed here are the ver 1.0 files and differ as listed
below. Only the macOS implementation has been verified on hardware by the author.

**ver 1.1 で、3つの実装が出力するかなは完全に一致しました。** ver 1.0 で食い違っていた
箇所は azooKey 表の側へ揃え、どちらかにしか無かった行も両方へ入れてあります。

macOS 版は Apple 日本語入力へ送るローマ字の綴りを訓令式（`ti` `tu` `hu` `zi` 等）に
揃えていますが、**出力されるかなは同一です**。

**As of ver 1.1 the three implementations produce identical kana.** Where the ver 1.0 tables
disagreed, the azooKey reading was adopted, and rows present in only one table were added to the
other. The macOS implementation emits Kunrei-shiki romaji to Apple Japanese Input, but the
resulting kana are identical.

### 変更履歴 / Changelog

#### ver 1.1

**ver 1.0 のテーブルに残っていた不具合をすべて修正しました。** `y` と `■x` の二重定義、
`{` `}` の区切りタブ欠落、`■#` `■4` `■:` の制御文字混入、`■?` の出力破損、azooKey 表の
`■~` `■|` の区切り破損です。Google 表と azooKey 表の食い違い（`■n` `■m` `■;` `■,` `■<`
`■.` `■>` `■/` `■|`）も azooKey 側へ揃え、Google 表にしか無かった `■[` `■]` `■{` `■}` →
「［」「］」「《」「》」を azooKey 表へ追加しました。**これで3実装の出力が完全に一致します。**

配列そのものの変更は次の4点です。

| 変更 / Change | 理由 / Reason |
|:---|:---|
| `W` `J` のかなを「ヴ」から「ゔ」へ | ひらがな入力でカタカナの「ヴ」を直接出す綴りが無く、確定してしまうと「ゔぁ」等を作れないため。「ヴ」は変換で得ます |
| `Q` `Y` → 「ヵ」を追加 | 「ヶ」は `E` `Y` にあったのに「ヵ」に対応キーが無く、捨て仮名の組み合わせでも作れなかったため |
| 捨て仮名の後置形8件を削除 | 母音キーの次の `T` を必ず吸い、`K` `T` `;` が「いぇ」ではなく「ぃえ」になるなど、基本かな＋捨て仮名の組み合わせを潰していたため |
| `■` `I` / `■` `O` → 「【」「】」を追加 | 数字段の無いキーボードでは `■` `(` / `■` `)` がレイヤー押しになるため、ホーム段から転がせる別名を用意 |

この4点により、**Apple 日本語入力のローマ字入力で打てるかな206種すべてが入力できるように
なりました**（詳細は [wkr-macos の網羅状況](https://github.com/yuhkis/wkr-macos/blob/main/docs/layout-coverage.md)）。
